# Project Overview

## Project Introduction

In this project, you will identify credit card customers who are most likely to churn. Your completed project will be a Python package that follows Python coding standards (PEP 8) and software-engineering best practices. The code will be modular, documented, tested, and runnable interactively or from the command-line interface (CLI).

This project gives you practice with testing, logging, and clean-code principles. It also introduces a common data-science problem: how can a company identify - and later intervene with - customers who are likely to churn?

## Choose Where to Work

You may complete the project in the Udacity Workspace or in a repository hosted on GitHub or Azure DevOps. The implementation and evaluation requirements are the same for every option.

### Udacity Workspace

The Workspace contains the project files, dataset, and required dependencies. If you want to work locally, first start the Workspace and download the contents of the `data` folder. This ensures that you use the dataset supplied for the project.

### GitHub

You may download, fork, or clone the public [project starter repository](https://github.com/udacity/cd0580-project-starter) and work in your own GitHub repository.

### Azure DevOps

You may import the public starter repository into an Azure Repos repository and work in a private Azure DevOps project. New public Azure DevOps projects cannot normally be created, so your Azure Repos URL might not be accessible to a Udacity reviewer. This is expected.

Do not invite an unknown reviewer to your Azure DevOps organization, expose confidential information, or weaken your organization's security controls. The Project Submission page explains how to submit a fresh-clone ZIP for offline review.

For repository import, authentication, branches, and pull requests, use the current **GitHub to Azure DevOps Translation Guide** earlier in this course.
